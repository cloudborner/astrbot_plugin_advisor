# 插件顾问

插件顾问会阅读去身份化的群聊内容，理解群里真正需要哪些机器人能力，再结合服务器余量、插件市场、资源占用、兼容性、维护情况和已安装插件给出建议。

它只提供建议，不会自行安装、更新或删除插件。

运行要求：AstrBot 4.26.7 或更高版本，兼容当前 4.26 系列和 5.x。

## 安装和首次设置

从 AstrBot 插件市场安装后，在配置页完成以下设置：

1. 在“QQ号白名单”中填写允许使用插件的QQ号。
2. 选择“群需求分析模型”，或留空使用当前会话模型。
3. 保存配置并重新加载插件。

图片内容分析默认开启，也可以按群的实际情况调整推荐数量。白名单为空时，所有人都无法使用插件顾问命令。

两个私聊附加权限开关默认关闭：默认只要QQ号在插件白名单中，就可以在私聊指定机器人能够读取的群。需要更严格限制时，可分别开启“私聊操作要求本人在群内”和“私聊导出要求本人为群管理员”。

## 命令列表

| 命令 | 作用 |
| --- | --- |
| `/需求分析 [群号]` | 群内分析当前群；私聊时指定目标群，读取聊天并生成待确认词组。 |
| `/确认分词` | 确认当前词组并开始模型分析和插件推荐。 |
| `/取消分析` | 清除当前尚未完成的临时分析草稿。 |
| `/最近需求分析 [群号]` | 查看24小时内最近一次有效报告的时间、需求和推荐摘要。 |
| `/重发需求分析 [群号]` | 不调用模型，使用最近一次安全检查点重新生成并发送报告。 |
| `/资源画像 <插件名>` | 同时查看插件功能、适用场景和静态性能占用估计。 |
| `/插件体检` | 查看服务器余量和资源资料状态。 |
| `/导出聊天记录 [群号]` | 群内导出当前群；私聊时指定目标群，格式与时间范围由高级设置控制。 |

### 词组编辑命令

| 命令 | 作用 |
| --- | --- |
| `/显示全部分词 [页码]` | 分页查看默认隐藏的其他词组。 |
| `/修改分词 <序号> <新词组>` | 修正一个词组，编号保持不变。 |
| `/删除分词 <序号>` | 删除不应参加分析的词组。 |

## 分析当前群

在群里发送 `/需求分析`，插件会直接读取最新聊天并生成词组确认页，不再要求重复发送“确认”。

此时模型还没有被调用。你可以先检查、修改或删除词组；只有执行 `/确认分词` 后，模型才会读取本次去身份化聊天并生成插件建议。

## 在私聊中分析群

白名单用户可以在私聊中使用 `/需求分析 <群号>` 选择目标群。默认不要求调用者本人加入该群；机器人仍必须已经加入目标群，并且当前平台能够读取群历史。开启“私聊操作要求本人在群内”后，插件才会额外校验调用者的群成员身份。

后续的词组查看、修改、删除和确认方式与群内分析相同。草稿会同时绑定调用者和目标群，不能用于其他群。
同一调用者再次开始其他群的分析时，会用新草稿替换尚未确认的旧草稿，避免私聊命令误操作到旧目标群。

## 图片分析

- 图片分析默认开启，默认最多选择 8 张。
- 图片会在聊天时间范围内分散选择，并自动去除重复或无效引用。
- 当前分析方式能够查看图片时，报告显示“图文分析”和实际分析数量。
- 当前分析方式不能查看图片时，插件会继续进行文字分析，并在报告中明确说明图片未被分析。
- 单张图片失效不会中断整个分析。
- 插件不会下载、抽帧、上传或识别视频；视频只计入消息数量统计。

## 推荐结果怎么看

推荐分综合考虑群需求、市场使用情况、AstrBot 兼容性、服务器资源、维护状态、部署难度、外部服务和插件冲突。一次明确提出的机器人任务也可以形成低优先级潜在需求；部分匹配但值得尝试的插件会保守展示，而不是直接丢弃。

高级设置中的“确认需求后的候选选择方式”提供两种模式：

- **本地检索**：兼容默认，先用需求和市场资料找到候选，再交给模型复核。
- **全市场模型分批选择**：固定本次市场快照，将每一个插件的简表按输入大小分批提交模型，由模型关联已确认需求并提名候选。缺少画像、画像过期、低热度或关键词不匹配都不会在目录阶段排除插件；过期画像使用市场描述回退。提名候选再分批查看详细资料，最终评分仍由本地计算。

启用全市场模式后保存配置并重新加载插件。该模式会增加模型调用和等待时间，确认页会提前提示。目录扫描默认总时限 600 秒，详情复核默认总时限 240 秒，二者独立于聊天需求分析；单次调用仍受模型等待时间限制。管理员可以在高级设置调整这两个总时限。

全市场模式会为每项需求能力核对消息引文和意图，区分要求、排除与对比说明。候选详情逐项给出支持、部分支持、资料不足或不支持，并引用插件资料；推荐理由按这些校验结果生成。

报告显示本次快照总数、已提交条目、有效响应覆盖条目，以及候选详情复核范围。单页格式错误或单次超时最多在总预算内恢复一次；未知插件或需求不予恢复。失败会保留其他批次的有效结果，并标明未完成。完整提交简表不代表模型绝不会漏选；目录描述有长度上限，不等于逐项阅读全部源码或 README。每页最多提名 20 个候选，详情复核不再套用本地的 32 项截断。

功能画像记录来源、版本和置信度，只辅助判断候选功能，不能代替群聊证据。推荐必须经过模型功能复核和本地评分，资料不足时允许不推荐。逐页进度只保存到有时限的安全报告检查点；`/重发需求分析` 仅重发已保存报告，不恢复扫描、不额外调用模型。

资源占用分为四档：

- 轻量：通常适合低配置服务器。
- 一般：使用时可能出现一定峰值。
- 较高：低内存服务器需要谨慎。
- 重型：可能包含本地模型、浏览器、媒体处理或较重后台任务。

资源档级来自源码与公开资料的安装前估计，不等同于真实运行时测量。资料不足的新插件会标记为“估计”或“未知”。

已经安装的同一插件、同仓库插件或重复分支会自动排除。如果现有插件已经覆盖主要需求，报告会直接说明，不会为了凑数量继续推荐。

聊天记录导出格式支持 JSON、JSONL 和 TXT，时间范围支持全部、最近24小时、最近3天、最近7天和最近30天；两项都在插件配置页的“高级设置”中选择。导出文件包含聊天正文；请只把白名单授予可信账号，完成后妥善保存或删除导出文件。

## 隐私和日志

- 模型只接收去身份化且有长度上限的分析内容，不接收QQ号、昵称、明文群号或凭据。
- 临时聊天上下文会在确认、取消或超时后清除；长期文件不保存聊天原文。成功分析会短期保留一份去身份化的派生报告检查点，24小时后失效，用于免 Token 重发；其中不含群号、账号、昵称、原始消息、完整提示词或模型原始输出。
- 报告只在末尾标注群号；使用远程图片渲染时，报告内容会发送到 AstrBot 配置的渲染端点。
- 插件日志直接写入 AstrBot 统一日志，只记录阶段、状态、数量、耗时、模型调用次数、可用时的 Token 计数和安全错误原因，不记录聊天原文、账号或模型输出。

## 卸载与数据

卸载插件不会自动删除已经导出的聊天记录。插件运行数据和导出文件位于 AstrBot 为插件分配的数据目录中；确认不再需要后，可由管理员手动删除。
