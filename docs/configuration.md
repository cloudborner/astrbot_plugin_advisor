# 插件顾问配置说明

插件安装后，在 AstrBot WebUI 的“插件管理 → 插件顾问 → 配置”中编辑。默认值已经覆盖
常见场景，通常只需保存一次即可使用。插件只提出建议，不会自动安装、更新或执行候选插件。

## 常用设置

常用设置只保留 4 项：

| 配置 | 默认 | 作用 |
|---|---:|---|
| 启用群聊需求分析 | 开启 | 使用去身份化聚合特征理解群用途；关闭后仍按服务器资源和市场数据推荐。 |
| 每次推荐数量 | 8 | 控制一份报告中的候选数量，范围 1–20。 |
| 报告详细程度 | 标准 | 可选精简、标准、详细。 |
| 群需求分析模型 | 当前会话模型 | 留空自动使用当前模型；无可用模型时自动使用内置规则。 |

不再需要用户配置市场地址、GitHub 回退、签名资源索引、评分权重、主题词、正则表达式、
停用词、网络重试、缓存或安全限额。这些内容随插件版本维护，旧配置中的对应值会被忽略。

## 高级设置

“高级设置”会正常显示在配置页面中，默认值已经适合大多数群。只有确实需要改变报告形式、数据保留或模型使用方式时才需要展开修改：

| 配置 | 默认 | 范围/作用 |
|---|---:|---|
| 优先发送图片报告 | 开启 | 将主要报告渲染为图片；生成失败时自动改发文字。 |
| 记录日志 | 开启 | 方便排查市场请求、模型分析和图片生成问题；关闭后插件不主动记录运行日志。 |
| 形成群需求结论的最少消息数 | 30 | 5–1000；样本不足时不调用模型。 |
| 去身份化聚合统计保留天数 | 30 | 1–365；到期自动清理。 |
| 最低推荐分 | 40 | 0–100；过滤明显不适合的常规候选。 |
| 允许模型理解去身份化群需求 | 开启 | 关闭后只使用确定性规则。 |
| 允许模型复核资料不足的插件 | 关闭 | 开启后会增加模型调用；模型只能补充未知或提高风险，不能降低已知风险。 |
| 单次模型分析超时 | 45 秒 | 5–120；超时自动回退到确定性结果。 |

## 群聊如何整理成模型容易理解的结构

插件不会把整段聊天直接塞给模型。每条群消息在当前事件内存中经过清洗、分词和计数后立即
丢弃原文，形成按天聚合的 `schema_version: 2` 摘要：

```json
{
  "sample": {
    "observed_messages": 120,
    "eligible_messages": 114,
    "duplicate_messages": 6
  },
  "content_mix": {
    "counts": {"text_messages": 100, "images": 12, "videos": 4, "links": 18}
  },
  "top_terms": [
    {
      "feature_id": "term_…",
      "term": "robomaster",
      "message_count": 24,
      "document_ratio": 0.2105
    }
  ],
  "cooccurrences": [
    {"feature_id": "pair_…", "term_ids": ["term_…", "term_…"], "message_count": 9}
  ],
  "trends": [
    {
      "feature_id": "term_…",
      "recent_7d_message_count": 18,
      "previous_7d_message_count": 6,
      "delta": 12
    }
  ],
  "intent_counts": {"search": 16, "download": 8},
  "commands": {"攻略": 5}
}
```

这个结构给模型保留了“大家在聊什么、哪些词一起出现、近期是否升温、内容和操作偏好”，同时
去掉发言顺序、完整句子、发送者身份和明文群号。摘要总大小不超过 20 KiB，高频词、命令和
共现至少要由 2 条不同消息支持才可持久化或交给模型。插件不读取平台昵称字段，但聊天正文里
重复出现的称呼可能成为聚合词项，因此这是去身份化摘要，不是绝对匿名数据。

聚合特征只在用户运行相关推荐或分析命令时发送给所选或当前会话模型，不会随每条群消息被动外发。
不希望数据离开服务器时关闭“启用群聊需求分析”；需要保留本地统计但禁止模型分析时，在高级
设置中关闭“使用模型理解群需求”。

同一规范化消息每天最多计入 3 次内容量，且只让第一份贡献词义特征，因此复制刷屏不能把一个
词刷成群需求。群标识使用本地随机盐哈希；消息哈希只在内存中用于去重，不写入统计文件。

## 模型与本地评分的职责边界

模型可以根据高频词、共现和趋势发现内置主题之外的新需求，例如特定游戏 Wiki、赛事资料或
角色扮演优化，但每个新需求必须引用摘要中的 `feature_id`。插件随后在本地将能力词与官方市场
元数据匹配，并限制模型新增需求的影响强度。

模型不能：

- 选择或伪造插件 ID；
- 修改固定评分权重、资源风险或市场使用分；
- 读取完整聊天、QQ 号、平台昵称字段或明文群号；
- 调用工具、下载源码或触发插件安装；
- 把聊天中的指令当作系统指令执行。

模型不可用、超时、返回格式错误或证据引用不存在时，插件自动忽略模型结果并使用内置规则。

## 固定评分

推荐总分固定为：群聊需求 30、市场使用 20、平台/版本兼容 20、资源适配 15、维护活跃 10、
部署复杂度 5。市场使用的 20 分固定拆成累计下载 13 分和 GitHub Stars 7 分，采用对数百分位。
配置页不提供修改权重入口。

## 旧版配置迁移

0.1/0.2 版的扁平配置和旧分组中，仍保留意义的 11 个常用/高级字段会被兼容读取。已删除的
市场地址、GitHub、索引更新、自定义规则、评分权重和安全限额字段不会再影响运行，插件统一
采用当前版本的受控默认策略。

## 常见问题

### 开启后为什么没有立即形成群需求？

默认需要 30 条有效群消息；相同文本刷屏不会增加语义样本。达到门槛后使用 `/需求分析`，再按
提示发送 `/需求分析 确认` 重新生成当前需求报告。

### 模型不可用还能推荐吗？

可以。服务器资源画像、官方市场数据、内置主题识别和固定评分都不依赖模型。模型只是为未知
资源特征和新兴群需求提供受约束的补充分析。

### 为什么页面里找不到关键词、正则或 GitHub Token？

这些不是普通用户需要维护的配置。关键词和安全规则随插件版本更新；GitHub 只访问公开 API，
失败时使用离线快照和市场元数据。插件不会读取浏览器 Cookie、密码库或本机 GitHub CLI 凭据。
