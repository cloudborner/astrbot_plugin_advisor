# 增量需求记忆评估

更新时间：2026-08-30

## 结论

0.9.0 不实现跨分析周期的增量需求记忆。当前完整连续窗口加分层综合已经覆盖单次长上下文；立即持久化“群需求记忆”会扩大聊天派生数据的保留范围，并可能把过期、玩笑或单次事件长期带入后续推荐。安全检查点只解决24小时内的报告恢复与重发，不参与下一次需求判断。

## 可借鉴的增量机制

- 使用“时间戳 + 边界消息 ID”游标，避免同秒消息遗漏或重复。
- 先原子保存批次，再推进游标；保存失败时不得宣称批次已经处理。
- 批次有确定性 ID、固定大小、最大保留期和全局数量上限。
- 最终报告由多个已校验批次合并，不能直接累计模型置信度或把单批次高重要性沿用到长期状态。

## 实施前必须满足的门槛

1. 默认关闭并明确告知会保存跨批次派生需求；支持按群清空和全局关闭。
2. 群索引继续使用安装级 HMAC，不保存账号、群号、原始消息、完整提示词、模型原始输出或图片内容。
3. 每条记忆只保存规范化能力、独立批次数、首次/末次时间和不可逆证据计数；不保存可还原聊天的摘要或逐条证据文本。
4. 至少两个不重叠批次支持同一能力后才能进入长期候选；单批次只作为待确认状态。
5. 使用时间衰减和最长保留期，不能简单累加置信度、频次或重要性。
6. 新一次完整分析与用户修改后的确认词组优先级高于旧记忆；冲突时降低或清除旧结论。
7. 在约2 GiB服务器上验证存储、合并、清理和并发峰值，且不得增加并行模型调用。
8. 测试覆盖跨秒边界、重复批次、保存失败、过期清理、群隔离、隐私扫描和旧版本迁移。

满足以上条件后，才适合把增量记忆作为独立、可关闭的后续功能，而不是复用报告检查点或长期保存模型摘要。
