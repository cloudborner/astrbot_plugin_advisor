## 配置页验收

普通配置页面只显示：

1. 启用群聊需求分析；
2. 每次推荐数量；
3. 报告详细程度；
4. 群需求分析模型（可选，留空自动使用当前会话模型）。

7 个低频高级值仍由默认配置提供，但通过 AstrBot 官方支持的 `invisible` 属性从普通界面隐藏。市场地址、GitHub 静态回退、签名索引更新、自定义主题、关键词、正则、网络重试和安全限额都没有用户输入入口。Chrome 保存默认配置后，服务器 JSON 只包含 `general` 与 `advanced` 两组受控值；日志显示插件正常卸载并重新加载，没有插件异常。

## 群聊结构化分析与隐私

模型不会接收完整聊天文本。插件在本地先生成受限结构：

- observed、eligible、duplicate 样本计数；
- 消息内容类型占比；
- 达到隐私阈值的高频词和短语；
- 达到阈值的词语共现关系；
- 最近 7 天与此前 7 天的趋势；
- 下载、搜索、问答、创作、运维、陪伴等意图计数；
- 达到阈值的命令使用计数。

每个可引用特征都有临时 feature ID。模型提出新需求时必须引用输入中的 feature ID；模型不能直接指定插件、改变评分权重、降低已知风险或触发安装。模型提出的查询词只由本地确定性逻辑匹配市场描述、标签和分类，模型专用路径明确排除插件 ID、显示名与仓库地址。

隐私和资源边界：

- 原消息、账号、明文群号和会话 ID 不落盘，也不读取平台昵称字段；聊天正文中的称呼可能成为聚合词项，需按潜在敏感数据保护；
- 精确重复消息只在内存中用带盐哈希识别，哈希不持久化；
- 同一文本的语义特征只计首份，内容统计最多计 3 次，降低刷屏污染；
- 单条消息内重复不能跨过隐私阈值；
- 模型 JSON 载荷硬限制为 20 KiB，所有列表和计数均有上限；
- 模型不可用、超时或输出不合规时自动回退到内置确定性规则。

聚合特征只在用户运行相关推荐或分析命令时发送给所选/当前模型，不随每条消息被动外发；
不希望数据离开服务器时可关闭群聊需求分析。

相关测试覆盖 10 万条合成消息的有界内存/文件大小、1 万次重复回放、中文长词降噪、14 日趋势、共现阈值、旧统计文件迁移、提示注入边界、严格模型 JSON 校验和证据引用。
