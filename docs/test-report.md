## 真实服务器结果

插件部署到约 2 GiB 内存的现有服务器。启动日志确认 0.7.1、1834 条资源画像、WebUI 和 OneBot 适配器均成功就绪。部署前后只重启 AstrBot，LLBot 的启动时间保持不变。

NapCat 4.18.19 使用容器内持久化 QQ 数据目录。扫码登录后重启容器，日志确认能够快速登录，未再次要求扫码。临时启用仅容器网络可访问的 OneBot HTTP 端点进行验收后已恢复原配置，并确认端点关闭。

真实历史验收直接调用插件的 `OneBotHistoryProvider`：请求上限 220 条，最终获得 220 条，调用历史接口 13 次；消息 ID 去重、时间顺序、文本及媒体组件归一化均通过。该过程只输出汇总数字，不输出群号、发送者标识或聊天正文。

真实模型验收使用合成的匿名连续对话和临时测试图片，不读取或打印模型密钥、聊天原文、账号、群号、模型正式名称或完整请求响应。每次返回的消息和图片证据都经过本地校验；三次连续运行分别耗时约 12～16 秒，临时图片均已删除。

服务器端报告验收直接调用 AstrBot 4.26.7 自带的 HTML 渲染链路。两张压力样图宽度均为 1080 像素，完整高度分别为 3263 和 3852 像素；图片可重新打开验证，未出现空文件或截断。

三容器共同运行时，AstrBot 约 514 MiB、LLBot 约 151 MiB、NapCat 约 349 MiB（限制 700 MiB），主机可用内存约 562 MiB、可用 Swap 约 599 MiB。三者均为 `OOMKilled=false`、`RestartCount=0`，最近 30 分钟内核日志没有新 OOM。

## 隐私检查

- QQ号、明文群号、昵称、聊天原文、图片内容和模型请求响应不写入分析审计。
- 未授权用户只收到“没有权限”，不回显其 QQ 号、白名单内容或内部配置。
- 插件异常日志只保留错误类型；聊天导出失败日志不写目标群号。
- 长期统计以带盐群键和有限计数保存，元数据明确标注不保存原始消息和明文群号。
- 导出聊天记录是白名单用户主动执行的独立功能；导出文件含正文，README 已提示管理员妥善保存或删除。
- 部署时未发现插件专用旧 `.log` 文件，因此没有误删 AstrBot 或其他插件共用日志。

## 仍需动作前确认的真实账号交互
