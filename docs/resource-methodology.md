# 静态资源画像方法

## 数据来源

生成器按以下顺序使用只读数据：

1. AstrBot 官方市场 JSON：插件 ID、版本、仓库、描述、标签、平台/版本声明、Stars、下载量和更新时间。
2. GitHub REST `git/trees/{ref}?recursive=1`：文件路径、类型、大小和树 SHA。
3. GitHub REST `dependency-graph/sbom`：仓库公开的依赖包名称；404 记为未知，不视为轻量证据。
4. 确定性规则：根据描述、路径和包名匹配浏览器、FFmpeg、下载器、图像处理、本地 ML、向量库、数据库、后台调度和 Web 服务等特征。
5. 仅在画像缺失/过期且规则仍含糊时，允许大模型读取上述结构化事实补充分类。

不使用 `git clone`、源码压缩包、GitHub Contents API，不导入或执行被扫描插件。

## L0–L4 解释

这些区间是安装规划用的增量风险带，不是性能承诺：

| 等级 | 内存（大致增量） | CPU 峰值（单核百分比） | 磁盘/网络含义 |
| --- | --- | --- | --- |
| L0 | <20 MiB | <5% | 可忽略或无明显持续活动 |
| L1 | 20–80 MiB | 5–20% | 少量缓存/请求 |
| L2 | 80–250 MiB | 20–60% | 中等任务型占用 |
| L3 | 250–700 MiB | 60–100% | 高负载，低配机需限并发 |
| L4 | >700 MiB 或不可控峰值 | >100% 或多核密集 | 大模型、浏览器、转码或大量下载等重任务 |

空闲和峰值分别评级。磁盘/网络的等级表示增长和带宽风险，不直接映射为固定字节数。

## 版本绑定和更新判断

每条画像包含 `plugin_id`、市场 `version`、GitHub List Commits（`per_page=1`）元数据接口返回的 `commit_sha` 和扫描时间。扫描器不调用可能附带文件 patch 的 Commit 详情接口。Git Trees API 仅提供路径、类型与大小证据；树对象 SHA 不会冒充提交 SHA。
插件运行时先比较市场版本；不一致即视为过期并触发只读增量分析。若能获取最新 commit，也可进一步比较 SHA。

## 已知局限

- GitHub API 元数据无法证明运行时并发、输入大小、缓存策略和内存泄漏。
- Tree 路径或包名只能说明“存在相关特征”，不能证明代码路径一定执行。
- SBOM 可能未启用或不完整；缺失会降低置信度，不会自动判断为轻量。
- 外部二进制、容器服务和远程 API 的实际成本取决于用户配置。
- 推荐结果必须在目标服务器上以单插件、低并发方式验证，不能在生产机批量安装全部市场插件。

规则位于 `data/resource_rules.json`，只允许 L0–L4 范围内的单调风险影响。三个以上重特征同时命中时，峰值内存和 CPU 各再提高一级，上限 L4。
